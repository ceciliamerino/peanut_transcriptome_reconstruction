# Protein analysis

This directory documents post-TransDecoder protein processing, protein-length summary statistics, and DIAMOND BLASTp homology assessment for the final peanut transcriptomes.

The same workflow was applied to the final transcriptomes generated using the read-classification-based and genome-guided reconstruction strategies.

## 1. Protein-sequence deduplication

Predicted protein sequences generated by TransDecoder were deduplicated by sequence using SeqKit v2.10.1.

The recovered command used:

`seqkit rmdup -s predicted_proteins.pep -o unique_proteins.pep`

The `-s` option removes duplicate sequences based on the full sequence.

This step was applied independently to the predicted proteins from each genotype and reconstruction strategy.

A generalized implementation is provided in:

`01_seqkit_deduplicate.sh`

## 2. Protein-length summary statistics

Protein-length statistics were calculated from the deduplicated protein FASTA files.

For each genotype and reconstruction strategy, the following metrics were calculated:

- number of unique protein sequences (N)
- median protein length
- 99th percentile of protein length (P99)
- maximum protein length

Protein lengths were calculated in amino acids from the FASTA sequences.

The original analysis appended one row per genotype and reconstruction strategy to a tab-separated summary table.

A generalized implementation is provided in:

`02_protein_length_summary.py`

The optional violin-plot section present in an earlier version of the original script was not retained because it corresponded to an earlier figure version and was not part of the final analysis presented in the manuscript.

## 3. Preparation of DIAMOND BLASTp output

DIAMOND BLASTp results generated during ORF prediction were processed from standard `outfmt 6` format.

The 12 standard columns were assigned as:

- query
- subject
- percent identity
- alignment length
- mismatch
- gap open
- query start
- query end
- subject start
- subject end
- E-value
- bit score

The processed tables were saved as CSV files for downstream homology analysis.

A generalized implementation is provided in:

`03_prepare_diamond_output.py`

## 4. Pooled protein-homology assessment

Processed DIAMOND results from the six final transcriptome datasets were pooled:

- Granoleico, read-classification-based
- Granoleico, genome-guided
- FAVar-2, read-classification-based
- FAVar-2, genome-guided
- Ascasubi, read-classification-based
- Ascasubi, genome-guided

For each dataset, the following DIAMOND-derived variables were retained:

- bit score
- alignment length
- percent identity

The six datasets were concatenated into a single pooled dataset for the final protein-homology assessment.

Spearman rank correlations were calculated for:

1. alignment length versus bit score, and
2. percent identity versus bit score.

The pooled dataset was also used to generate:

1. bit score versus alignment length,
2. bit score versus percent identity, and
3. percent-identity distribution with a broken Y axis.

The histogram used 30 bins and included a kernel density estimate.

A generalized implementation is provided in:

`04_plot_pooled_diamond.py`

## Workflow

Predicted proteins from TransDecoder  
→ SeqKit sequence deduplication  
→ unique predicted proteins  
→ protein-length summary statistics

DIAMOND BLASTp `outfmt 6`\
→ processed DIAMOND CSV files\
→ pooling of the six genotype × reconstruction-strategy datasets\
→ Spearman correlations and protein-homology plots

## Scripts

- `01_seqkit_deduplicate.sh` — removes duplicate predicted protein sequences using SeqKit.
- `02_protein_length_summary.py` — calculates N, median, P99, and maximum protein length from unique protein sequences.
- `03_prepare_diamond_output.py` — converts standard DIAMOND BLASTp `outfmt 6` results into labeled CSV tables.
- `04_plot_pooled_diamond.py` — pools processed DIAMOND results from all six datasets, calculates Spearman rank correlations, and generates the final protein-homology plots.
